# 关键架构决策

每条：决定、放弃的替代方案、后果。评测数据与已知缺陷见 [evaluation-report.md](evaluation-report.md)。

## 1. 权限在召回 SQL 内生效，且失败即关闭

- **决定**：`AccessScope` 由 `knv_kb_grant`（区域 / 部门 / 角色，NULL 为通配）算出可读知识库集合；稠密与稀疏两条召回的 SQL 都带 `kb_id = ANY(:readable)`。集合为空或权限查询出错时抛 `NoAccess`，不检索。`knv_chunk` 冗余 `kb_id`，让预过滤只需一个索引条件。
- **替代**：先检索、再按权限过滤结果。
- **为什么不选**：未授权块会进入候选、融合、精排乃至模型上下文，任何一处遗漏都是泄露；后置过滤还会让 Top-K 被无权块挤占。
- **后果**：HNSW 带过滤时可能少返回结果，已开启 `hnsw.iterative_scan`；MVP 规模下可以接受，大库需要重新评估分区或按知识库建索引。

## 2. 身份只来自服务端，作用域每次重算，不缓存答案

- **决定**：用户身份、区域、部门只从 token 对应的数据库行读取；`user_id` 通过 LangGraph `configurable` 注入，不放进模型可改的状态；每次工具调用重新计算 AccessScope。MVP 不做答案缓存。
- **替代**：在会话开始时算一次作用域并缓存；用语义缓存提高命中。
- **后果**：撤权在下一次工具调用即生效；没有跨用户缓存泄露路径。若以后加缓存，键必须包含权限指纹。

## 3. 单个 PostgreSQL（pgvector）承载向量、业务表和 Checkpoint

- **决定**：稠密 `vector(1024)` 与稀疏 `sparsevec` 同表同库，LangGraph Checkpointer 用同一实例的独立 schema（`knv_checkpoint`）。无 Redis、Celery、Elasticsearch。
- **替代**：ES 做关键词通道、Redis 做会话、Celery 做异步入库（v2.0 方案）。
- **为什么不选**：资料量小，同步入库足够；基础设施越少，越能把精力放在权限、版本、引用上。
- **后果**：入库是同步的；关键词通道只有 BGE-M3 稀疏向量，没有 BM25 对照。

## 4. 混合检索：BGE-M3 稠密 + 稀疏，RRF 融合

- **决定**：一次编码同时得到稠密与稀疏向量；各召回 Top-20，用 RRF（k=60）融合，Rerank 为可关闭的可选项。
- **替代**：只用稠密；稠密 + 独立 BM25。
- **后果**：精确故障码、型号靠稀疏通道；RRF 是**排序**融合，不提供可比较的置信度，因此不能用来做拒答闸门（见第 8 条）。

## 5. 简繁处理：归一化只用于稀疏侧，展示永远用原字形

- **决定**：入库时保存原文，另存 OpenCC 转简体的文本，只用它生成稀疏向量；稠密向量用原文（BGE-M3 本身跨简繁）。来源片段显示原字形，回答跟随提问者的字形。
- **查询编码补充**：显式编码的全角、大小写与横线先统一为规范写法，再分别进入稠密侧和 OpenCC 稀疏侧；这一格式归一化不转换简繁字形，也不修改来源原文。
- **替代**：全库转简体后统一检索与展示。
- **后果**：不丢失繁体原文；在当前小语料上 OpenCC 没有可测收益，价值需要更大语料确认。

## 6. 修订发布是一个事务，检索只读 PUBLISHED

- **决定**：新修订先以 DRAFT 写入全部块，发布时在同一事务里把旧修订置为 RETIRED、新修订置为 PUBLISHED；检索的 SQL 只连接 `status = 'PUBLISHED'`。
- **替代**：覆盖更新原块；用时间戳在查询时选最新版本。
- **后果**：发布失败时旧版本继续生效，不会半发布；已退役修订的块仍保留，供回放预览。

## 7. 检索是确定性工具，Agent 受预算约束

- **决定**：检索流程（作用域 → 召回 → 融合 → 闸门）固定为 `search_knowledge` 工具内的确定性步骤，不让模型自治地决定如何查；Agent 图为 `agent → tools → … → cite_check`，每轮最多 4 次工具调用，超限给出 `RUN_LIMIT`。
- **替代**：让 Agent 自己选择检索策略与知识库。
- **后果**：权限与版本规则不依赖模型行为；代价是模型只能调整查询文字。

## 8. 证据闸门：相似度与精确编码分别检查

- **决定**：没有 Rerank 时，分数放行条件为稠密余弦 ≥ 0.60 **或** 稀疏内积 ≥ 0.03；有 Rerank 时用其分数。另加第 12 条的精确编码约束。模型仍须在资料不支持问题时以【无依据】开头声明拒答，`cite_check` 识别后清空来源卡并标记本轮为拒答。
- **替代**：用 RRF 融合分做闸门；只依赖提示词拒答。
- **为什么**：BGE-M3 稀疏通道对共有词也会命中，RRF 分与可答性无关；精确编码在稠密上分数可能偏低，只看稠密会误拒。E17-43 与 E17-42 在相似度上几乎无法区分，所以显式编码另做词面约束。
- **后果**：词面约束可拒绝当前候选中不存在的显式编码，但编码存在不代表来源支持问题；无显式编码的问题仍依赖模型，并有过度拒答的代价（历史结果见评测报告 9.4）。本轮不调整分数阈值或提示词。

## 9. 引用是证据注册表别名，伪造标识不渲染

- **决定**：本轮每条证据登记为 `S1…Sn`，模型只能用 `[S1]` 引用；`cite_check` 把未登记的标记删除，来源卡只来自已登记且被引用的证据。来源预览 `/evidence/{id}` 每次重新鉴权，无权与不存在都返回 404。
- **替代**：让模型直接输出文档名 / 页码；预览只校验登录。
- **后果**：来源一定对应真实检索结果；该机制保证“来源存在且已授权”，**不保证来源支持论断**，后者需要人工抽查。

## 10. 转交专家：interrupt 确认 + 幂等写入，以已存决定为准

- **决定**：`escalate_to_expert` 使用稳定 `operation_id`，落一条 `knv_confirmation` 后调用 `interrupt()`；新操作由 `(thread_id, 用户消息 ID, tool_call_id)` 派生并在工具状态中持久化，旧检查点保留原来的 thread/tool-call 派生规则（见第 20 条）。确认接口先匹配当前 interrupt，再用条件更新原子地认领决定（只有第一次生效），恢复时使用**已存储的决定**而不是请求体；执行节点按 `(user_id, operation_id)` 唯一约束 `ON CONFLICT DO NOTHING`。过期的确认以拒绝恢复，避免线程悬挂。
- **替代**：在工具里直接写记录；信任请求体里的 `approve`。
- **后果**：重复提交、刷新、进程重启后恢复都只产生一条记录，已拒绝的确认无法被翻转；节点会在恢复时从头重跑，所以其中的写操作必须是 get-or-create。

## 11. 评测集分层与防污染

- **决定**：60 例中 20 例为调参集，40 例为留出集，留出集需要显式 `--confirm-final` 才能运行；修复之后只用新写的用例验证。
- **后果**：任何改动都要用未用过的用例验证，评测集因此会随修复不断增加。

## 12. 精确编码是原始用户问题的约束，先鉴权再检查

- **决定**：识别含数字、以字母开头的连字符 ASCII 编码，规范全角 / 大小写 / 常见横线。模型检索词与本轮最后一条用户消息中的编码取并集。仅在权限 SQL 返回的候选正文与章节路径中匹配完整编码，先过滤再取 Top-K / Rerank；最终证据要覆盖全部编码，且每个编码至少有一条证据通过分数闸门。缺失时返回 `INSUFFICIENT_EVIDENCE`，内部记录 `IDENTIFIER_MISMATCH`，不向模型返回部分证据。
- **替代**：只提高分数阈值；只校验模型改写后的查询；扫描全库确认编码存在。
- **为什么不选**：提高分数会再次误拒；改写可删除或替换用户编码；扫描全库会跨越权限边界。仅匹配文档标题也不够，同一本手册中有不同故障章节。
- **后果**：模型重试、改写不能把不存在的显式编码换成真实近似编码。章节继承可支持正文未重复编码的操作步骤。多编码查询保守要求每次检索覆盖全部编码，分次检索可能被拒；仅检查现有候选，不保证完整召回，不证明来源支持论断。原 exact-v1 不解析分写编码，后续有界语法扩展见第 25 条。验证集 val4 为同一小语料上的针对性回归，结果见评测报告第 10 节。

## 13. Rerank 显式选模型，独立分数闸门，评测使用真实最终候选

- **决定**：Rerank 输入带章节路径，保留正文没有重复的故障码；查询沿用编码格式归一化。按 [FlagEmbedding 官方接口](https://github.com/FlagOpen/FlagEmbedding/tree/master/examples/inference/reranker) 使用 `normalize=True`，校验分数数量、有限性与 `[0, 1]` 范围；异常即检索失败，不退回其他分数放行。分数以独立 `KNV_RERANK_THRESHOLD` 配置，默认 0.60 仅延续原行为，不视为已校准的可答概率。
- **模型选择**：`KNV_RERANK_MODEL` 默认保留计划中的 `BAAI/bge-reranker-v2-m3`；本轮使用本地已有缓存的 `BAAI/bge-reranker-base`，在结果中明确记名，不把 base 的数字归于 v2-m3。仍默认关闭。
- **评测修正**：从同一次检索返回最终、闸门前的候选及分数；原运行器在计算 Recall / MRR 时另做普通检索，启用 Rerank 也只测到 RRF。新增 `rank_metric_stage` 明确口径。val5 正例用原文片段约束目标块；旧用例与历史结果不修改。不支持的 Agent 消融参数在加载模型前报错。
- **替代**：继续借用稠密阈值，省略章节；只看 Rerank 开关就把报告称为精排结果；看到一个小样本收益便默认启用。
- **后果**：val5 的 18 个有依据例两组均召回并通过闸门，只有 1 例的目标块从第 2 位升到第 1 位；检索中位延迟从 102.0 ms 到 117.6 ms。现有证据不足以默认启用，也未验证端到端净效果，详见评测报告第 11 节。

## 14. 回答支持度依赖当轮快照与具名审核，不事后拼接来源

- **决定**：Agent 评测为每例保存问题、最终答案、证据注册表、实际来源卡、错误码和内容校验值，并保留线程 ID、标准 CLI 的提示词哈希。离线审核逐句记录审核者、human / agent 类型、结论、理由与原文引句；工具验证引句位置和引用归属，不自动判断语义支持关系。
- **替代**：只凭“来源文档和页码正确”声称答案正确；拿当前库重新检索当作历史来源；让模型标签进入人工审核数字。
- **为什么不选**：同一文档页内也有不支持论断的片段，资料与检索顺序会改变，模型审核与人工判断的性质不同。旧报告缺少当轮来源快照时直接拒绝，不补齐假历史。
- **后果**：来源可复核且审核口径明确；未审核单元不会被算为支持，无已审核事实时支持率为 null。来源 / 论断 / 选择清单漂移会被检测，但校验值不是签名，引句存在也不证明语义支持。真实 LLM 的人工抽查仍待进行，详见 `backend/eval/REVIEW.md`。

## 15. 拒答控制标记同时接受简体与繁体

- **决定**：`cite_check` 接受开头的 `【无依据】` 与 `【無依據】`，两者都清空来源卡、移除标记和引用并设置拒答状态；保留答复正文原字形。
- **依据**：历史 val3 已出现繁体 `【無依據】`，原来的精确简体前缀判断漏掉该变体。此次只修正确定性识别，不修改系统提示词或按旧用例调参。
- **后果**：新增图级和 SSE 测试使用脚本模型验证两种写法，旧端到端报告不重写，也不把此次单元测试说成真实 LLM 净效果评测。

## 16. 会话恢复读取服务端状态，确认决定不由前端提前推断

- **决定**：前端打开会话与流式请求结束后读取本人 `/conversations/{id}/state`，恢复消息错误码和真实 interrupt 对应的确认卡。确认期间阻止发送新问题；请求失败后重新读状态，未保存的决定可以重试，已保存的决定按服务端状态恢复执行。过期确认仅提供关闭操作。
- **并发边界**：当前页面执行请求期间禁用会话切换，并在离开聊天页时取消浏览器请求、释放 SSE reader；取消浏览器请求不承诺回滚服务端执行，故下次打开仍以服务端状态为准。状态同步失败时保持发送禁用。
- **回放顺序**：消息默认时间由 PostgreSQL `now()` 改为 `clock_timestamp()`（迁移 `0003`）。前者是事务开始时间，同一事务内多条消息时间相同，按 UUID 排序可能颠倒消息。旧记录不回填，已有相同时间戳无法事后确定其真实顺序。
- **验证与限制**：133 项后端测试、9 项前端 API / jsdom 交互测试通过；构建通过，lint 保留登录页和 App 原有的两项警告。测试覆盖流程与归属校验，不构成真实模型人工支持度审核或浏览器录屏。

## 17. 先记录拒答路径，再区分检索失败和模型判断

- **决定**：每轮保存检索尝试的查询、状态、闸门原因和实际返回的证据 ID；模型拒答控制标记另行记录。追踪在新轮次清空，重试累积、确认恢复保留，且不加入模型消息。评测报告保存预期来源，与当轮快照共同供离线诊断使用。
- **替代**：仅从最终 `INSUFFICIENT_EVIDENCE` 推断失败层，或凭来源存在便宣称模型过度拒答。
- **后果**：离线工具可区分检索未返回证据、模型拿到证据后拒答与工具超限等运行错误。命中文档位置和命中目标原文分别统计，后者只标为人工复核候选。缺少追踪的旧报告拒绝分析，不复查当前库以重建历史。报告摘要绑定输入校验值，校验值不提供签名保证。
- **限制**：显式拒答率不覆盖未带控制标记的自然语言拒答；原文命中不是语义支持证明。保持提示词和阈值不变，真实模型的人工复核和过度拒答率测量仍待新评测完成。
- **验证**：完整后端回归 158 项通过，含 23 项离线诊断测试、2 项真实 Agent 图到分析工具的集成测试，以及跨轮重置和 interrupt 恢复断言。模型为脚本替身，不作为真实回答效果数字。

## 18. 文档级串行化与数据库约束共同保护版本发布

- **决定**：以 `(kb_id, title)` 唯一标识文档；首次上传用冲突忽略插入，随后锁定文档行，串行分配版本号。解析和编码先于锁操作，空正文或编码输出数量不足立即失败；修订语言必须与文档一致。API 验证失败回滚并返回 422。
- **发布**：所有发布者锁同一文档行，等待后重新加载修订状态，再在调用方事务内退役旧版、发布草稿。当前生效版重复发布不改状态或时间；已退役版、没有块的草稿拒绝发布。数据库部分唯一索引额外保证同一文档最多一个 PUBLISHED，防止绕过服务的写入破坏该约束。
- **替代**：仅依靠批量 UPDATE 的事务原子性；只在内存里读一次状态；用 `zip` 默默丢弃缺失的编码结果。事务原子性不能替代并发串行化，等锁之前读取的 ORM 对象也可能过期。
- **迁移**：`0004` 添加文档唯一约束和发布部分唯一索引；遇到已有重复文档或多个生效修订时事务失败，不自动合并或选择保留版本。升级后再启动新服务。
- **边界**：同步入库仍由请求方提交 / 回滚；并发发布按取得锁的顺序执行，不强制版本号单调递增。文档名精确匹配，不做标题同义或空格归一化。既有数据库和真实模型评测结果不在本轮自动改写。
- **验证**：完整后端回归 174 项通过；新增 14 项版本完整性测试和 2 项上传 API 验证错误测试。并发测试使用独立事务并观察 PostgreSQL 实际锁等待，迁移测试覆盖升降级保留数据以及重复文档 / 多生效修订时失败。

## 19. 会话写请求在服务端互斥，锁覆盖 SSE 生命周期

- **决定**：聊天和确认在校验归属后共用按 conversation ID 派生的 PostgreSQL session advisory lock。锁申请不等待，冲突返回 HTTP 409 / `CONVERSATION_BUSY`。获得锁后才检查待恢复状态或保存确认决定；前端分别提示会话正忙和待处理确认。
- **替代**：仅靠当前页面的 busy 状态，或仅靠转交记录唯一约束。前者覆盖不了其他标签页 / API worker，后者只能避免重复记录，不能防止两个运行交错更新检查点和消息。
- **生命周期**：独立连接持有 session 锁，业务事务提交不释放它；响应完成、send 失败或取消时先关闭迭代器再解锁。响应开始前的准备异常也释放锁。锁 SQL 往返或提交结果不确定时丢弃连接，防止可能仍持锁的会话回到连接池。
- **边界**：每条活动 SSE 占用额外一个数据库连接，需要直连或 session pooling，不支持 transaction pooling 代理。正在工作线程内执行的模型调用可能要完成后才能清理；不承诺客户端断连会回滚服务端已完成的动作。只读接口仍为当时快照；离线评测直接调用图，使用独立 thread ID，不走此 HTTP 锁。
- **验证**：完整后端回归 187 项、前端 10 项通过，前端构建通过；lint 保留两项原有警告。新增测试覆盖独立连接池互斥、真实并发 HTTP 聊天 / 确认、其他会话继续执行、跨用户 404、响应结束 / 断连 / 取消，以及不确定锁状态时丢弃连接。

## 20. 确认归属于当前 interrupt 和用户轮次

- **决定**：在会话锁内读实际 interrupt，确认 ID 必须匹配才能保存或恢复决定。线程有其他待执行节点、其他确认，或待确认数据库行已不在检查点时，返回 HTTP 409 / `CONFIRMATION_NOT_ACTIVE`；不改写决定，不恢复图。线程已完成时旧的已决确认仍可幂等回放。
- **跨轮身份**：新转交的 operation ID 包含 thread ID、当前 HumanMessage ID 和 tool-call ID，先写入 pending 图状态再进入确认节点。模型跨轮复用同一个工具调用 ID 时，新的用户请求仍创建独立确认。恢复同一轮时复用 pending 内的 operation ID。
- **兼容**：旧 pending 状态没有 operation ID 时，沿用原 thread/tool-call 派生，保证部署前已等待的确认在重启后恢复到原记录。无需迁移，不重写历史确认。
- **验证边界**：用真实图和数据库检查旧批准 / 拒绝的确认重放、跨轮相同工具 ID、孤立 PENDING 行、已存决定与重试请求相反、旧检查点重启；前端验证冲突提示和当前卡恢复。失败图节点的一般重试不属于确认接口，不以旧确认 ID 强行驱动非 interrupt 节点。
- **结果**：完整后端回归 194 项、前端 11 项通过，生产构建通过；lint 保留两项原有警告。新增 7 项后端测试和 1 项前端交互测试，未调用真实 LLM。

## 21. 失败检查点显式恢复，重试身份绑定到检查点

- **决定**：未完成且没有 interrupt 的检查点通过只读 state 接口返回 `retry_checkpoint_id`，前端显示“继续未完成请求”。新的用户消息在该状态下返回 `RUN_INCOMPLETE`；待确认状态仍走原确认流程，不混同运行失败和人工等待。
- **执行**：新增 `/chat/retry`，在本人会话锁内核对当前检查点。完成或待确认返回 `RUN_NOT_RETRYABLE`，检查点漂移返回 `CHECKPOINT_CHANGED`，并发返回 `CONVERSATION_BUSY`；均不写入新用户消息或决定。正确请求以 `None` 输入继续原图，保留工具预算、pending 参数、原操作身份和已存决定。
- **副作用**：失败节点可能重跑。现有只读工具可以重查，转交写工具按原 operation ID 幂等写入，覆盖提交后、节点返回前失败的情况。新工具必须先实现相应的重试保证。状态读取不自动执行，用户显式点击后才继续；模型调用可能再次计费。
- **边界**：只恢复已保存且仍有待执行节点的检查点；不重建已完成图但未持久化到消息表的答案，不替代数据库 / 模型服务恢复。失败记录保留在历史中，成功恢复后追加最终答复。无需数据库迁移。
- **验证**：完整后端回归 199 项、前端 13 项通过，生产构建通过；lint 保留两项原有警告。新增 5 项恢复测试和 2 项前端交互测试，并扩展真实并发 HTTP 测试验证 retry 共用会话锁；所有模型调用使用脚本替身。

## 28. Agent 评测逐例持久化，失败不发布完整指标

- **问题**：原运行器只在所有用例完成后写报告；后续调用或数据库故障会使此前已完成的回答没有文件记录，再跑整组可能重复付费。

- **失败边界**：异常 / Ctrl+C 尽力记 `run_failed` 并原样向调用者抛出；日志仅保存异常类名，避免持久化错误文本中的凭据。日志磁盘故障立即停止后续执行，失败标记写入失败不能掩盖原异常。既有日志 / 报告不覆盖，二者路径必须不同；预检和检索模式不创建日志。

- **范围**：本轮使用离线脚本 / 替身模型验证流程，不产生真实 LLM 调用，不新增数据库迁移，不改变 Web 聊天图。

## 30. 不把模型长度截断或无效工具调用当作完整回答

## 31. 工具 JSON 解析后仍须校验契约，整批通过后才执行

## 32. 纯检索回答须有有效引用，无证据拒答使用固定最终文本

- **问题**：原引用校验只删除未知来源标记，允许成功检索后的无引用回答正常结束；检索已拒绝时，模型仍可能忽略提示并在带拒答错误码的消息正文中生成操作建议。
- **决定**：当前用户轮次最近一次工具批次仅包含检索时，若最终回答无错误且没有任何注册来源引用，返回 `MODEL_CITATION_MISSING` 与固定错误文本，展示来源为空。保留原检索证据与追踪供诊断。若纯检索没有证据且已有 `NO_ACCESS` / `INSUFFICIENT_EVIDENCE`，返回固定拒答正文，模型是否带拒答控制标记仍记录在诊断中。

## 33. SSE 连接结束不等同于回答完成

- **问题**：原客户端在 reader EOF 时直接正常返回，半截事件和没有结束事件的 token 流可能被默认为正常结束；解析还只识别 LF 双换行及单行 data。
- **决定**：逐行解析 LF / CRLF / CR，保留跨字节 UTF-8 和换行边界，支持注释心跳与多行 JSON data。只有完整且有效的 `done` / `confirm` 作为终态，收到后取消 reader 并释放锁，不等服务器继续关连接。错误事件本身不代表终态，仍需 done / confirm。
- **失败**：终态前 EOF、无响应 body 或 reader 读取失败抛出 `STREAM_INCOMPLETE`；无效 UTF-8、JSON 或不符合当前事件字段类型的载荷抛出 `STREAM_INVALID`。确认卡需完整字段和有效日期，来源卡校验必需字段。解析失败、正常终止、消费者提前退出均清理 reader；用户主动取消沿用取消语义。
- **恢复**：前端提示失败后使用已有会话 ID 同步状态，完整保存的回答 / 待确认 / 继续 / 补存以服务端为准，不自动重发。同步失败保持阻塞；若首次请求的 metadata 尚未收到，则无法凭空恢复其 ID，需刷新列表重新打开核对。流式 token 仍为预览，不证明模型运行或业务写入是否完成。
- **未知会话**：首次中断且未收到会话 ID 时，显示专门提示并阻止继续发送，不声称已进行状态同步，也不猜测 ID；用户需从列表重新打开核对，或明确选择新会话。
- **范围**：本轮只改客户端解析与错误提示，不改后端 SSE 事件、数据库或模型调用；离线测试验证协议和交互，不替代真实浏览器弱网测试或录屏。
- **验证**：前端完整 47 项测试通过，新增 22 项覆盖换行与字节分片、正常来源卡、完成 / 确认后主动释放连接、终态缺失、损坏 JSON / UTF-8 / 卡片、reader 失败与无 body、已知会话状态同步及未知 ID 时阻塞。生产构建通过，lint 保留两项既有警告；后端未修改，本轮未重复后端回归。文件差异检查通过。

## 34. 来源预览取消后不得由旧响应重新打开

## 35. 资料管理区分提交结果与刷新结果，避免重复写入

## 36. 身份请求与当前凭据 / 路由绑定，旧 401 不影响新登录

- **问题**：原 App 复用已存 me 并在路由切换后异步刷新，旧请求可覆盖新身份；读取失败把 me 置空后一直显示加载。通用请求遇到任何 401 都清空当前凭据，无法区分请求使用的旧 token 和新登录 token。

- **凭据同步**：`setToken` 通知同页订阅者；相关 localStorage storage 事件通知跨标签页，清理事件监听避免卸载后继续订阅。原 token 被替换后到达的 401，以及已取消请求返回的 401，不能清掉新会话或强制跳登录；当前凭据的有效 401 仍清 token 并回登录。
- **权限边界**：管理员页面只在当前身份核对后按 role 挂载。它是客户端隔离与交互改善，不替代服务端每请求鉴权，也不持续监听后台权限变更。路由 / 凭据变化会卸载业务页并取消浏览器请求，不能撤销已经提交的业务；重新进入后以服务端记录为准。
- **范围**：不修改登录方式、JWT、后端权限或数据库，不调用模型。App effect 只在请求回调中更新身份，消除其既有同步状态更新 lint 警告；登录页原警告保留。历史 CI 验证记录不改写。

## 37. 登录只提交一次，过期结果不写入当前凭据

## 38. 上传按实际文件字节分块限额，超限不进入入库
