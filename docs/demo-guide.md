# Knoventra 演示与恢复验证

本指南对应开发方案第 3.4 节。所有账号和资料均为虚构数据。录制真实回答前按 README 启动数据库、升级迁移、导入演示资料，并配置模型；模型调用会产生费用。`backend/dev/mock_server.py` 使用固定回答，仅用于检查界面和流程，不能作为真实问答质量证据。

## 演示步骤

1. 使用 `sg-ops@example.test` 登录，确认顶部显示 SG / Ops。问「E17 设备报代码 42 先查什么」。检查来源卡的文档名、修订、页码和原文预览；回答与片段逐条核对。
   再问「E17 设备报代码 45 怎么处理」：受支持的分写语法会生成 E17-45 约束，候选缺失该码时确定性拒答，不应改答 E17-42。分写识别不覆盖温度、金额、范围或没有代码标签的数字。
2. 切换 `tw-ops@example.test`，用繁体问「循環泵 P03-11 壓力偏低先查什麼」。检查简体来源可被检索，预览保留原文字形。跨简繁效果以真实检索和模型结果为准。
3. 切换 `hr@example.test`，问同一个 E17 问题。检查没有 Ops 来源；猜测或使用其他账号的来源 ID 应返回 404。再用 `sg-ops` 问 FIN 预算，确认部门隔离。
4. 使用 Ops 账号问「E17-44 怎么处理」。检查拒答样式、没有来源卡；刷新并选择该会话，拒答状态仍应保留。显式编码不存在时使用确定性的编码约束；无编码问题仍依赖证据闸门和模型。
5. 新会话发送「转人工：E17-42 复位后仍报警」。出现确认卡后刷新页面，再从侧栏选择该会话。检查摘要、有效期和确认按钮恢复，发送按钮在处理确认前禁用。确认一次后应得到转交记录；重复提交不得创建第二条。另开一轮选择取消，应不创建记录。
   点击导航“转交记录”，核对本人记录的摘要、待处理状态和时间；刷新不重复新增，切换账号后不能看到原账号的记录。历史时间未知的记录显示明确标签；可用“加载更多”查看旧记录。
6. 管理员在资料管理中为相同知识库、同名文档上传 v2，先确认草稿不影响查询，再发布。重新用有权账号提问，检查只召回已发布版本。演示种子已包含 E17 v2 草稿，可先检查当前状态，避免覆盖现有演示数据。

## 恢复与失败路径

- 在流式回答期间，侧栏切换与新会话按钮应禁用，当前回答不会写入另一个会话。
- 两个标签页打开同一会话，在第一轮仍处理时从另一页发送或确认，应看到会话正忙提示（HTTP 409 / `CONVERSATION_BUSY`），不会追加第二条用户消息或改写确认决定；第一轮结束后重新打开会话再重试。其他会话仍可独立提问。
- 确认请求失败时，界面重新读取服务端状态；若决定未保存，仍可重试；若决定已保存，恢复处理使用已存决定。
- 第一轮转交处理完成后，在同一会话发起第二轮。重放第一轮的确认请求应返回 409 / `CONFIRMATION_NOT_ACTIVE`，第二轮仍保持待确认、记录数不变；只有第二轮确认 ID 可以驱动当前转交。两个轮次分别确认后应各有一条记录。
- 确认过期时只能关闭过期确认；关闭请求由服务端按有效期判定，不创建转交记录。
- 状态同步失败时发送按钮保持禁用，重新打开会话成功后才可继续。
- 模型或工具失败后重新打开会话：若检查点还有待执行节点且不在等待确认，会显示“继续未完成请求”。点击后沿用原问题继续执行，不再追加用户消息。旧检查点令牌不能恢复新任务；正在等待确认时也不能用该入口跳过确认。错误历史保留，恢复成功后显示最终回答。
- 若图已完成但最终消息保存失败，新的已跟踪轮次会显示“恢复已完成回答”，保存原答案 / 来源 / 拒答码，不重新调用模型。补存前不能发送新问题覆盖该轮；重复补存不产生第二条最终消息。没有轮次标记的旧记录不会被推测补造。
- 服务端最终答案为空时，界面清除之前的流式文本；不会以之前的 token 替代已校验的空答案。
- 收到部分 token 后连接结束但没有完整 `done` / `confirm` 时，界面显示连接中断提示并重新读取已知会话状态，不将半截文本当作成功结果，也不自动再次调用模型。状态同步成功后以已存答案或待恢复检查点为准；同步失败继续阻止发送。若新会话连 metadata 都未收到，先刷新会话列表并重新打开核对，不直接重复提交。

## 验证范围与交付

### 本地浏览器流程核对（2026-11-08）

在独立的 `knoventra_demo_20261108` PostgreSQL 库执行全部迁移，用离线 Hash 编码器导入 12 份虚构资料，并运行 `backend/dev/mock_server.py` 与 Vite 前端。在浏览器中逐项观察到：

- SG / Ops 提问 E17-42 后显示手册修订 1 的来源卡，预览给出同一修订、页码和原文；TW / Ops 使用繁体提问 P03-11 后显示简体泵组资料。
- HR 提问 E17-42、SG / Ops 提问不存在的 E17-44 时均显示无来源拒答态。
- SG / Ops 请求转交后出现确认卡；刷新并重新打开会话仍能恢复确认；确认后“我的转交记录”出现一条待处理记录。
- 管理目录原有 E17 修订 2 为草稿、修订 1 生效；显式发布后目录显示修订 1 退役、修订 2 生效，随后新问题的来源卡标为修订 2。

这次手动核对只证明本地 UI / API 流程可操作。脚本模型提供固定回答，Hash 编码器不代表 BGE-M3 的检索效果；该次核对没有录屏，也没有产生真实 LLM 回答支持度指标。

2026-11-08 另用全新的独立演示库录制了[23 秒无声浏览器流程视频](demo/knoventra-mock-flow-20261108-final.mp4)，覆盖五个故事及版本发布后的新来源；编码与录制范围见[视频说明](demo/README.md)。此视频仍使用脚本模型和 Hash 编码器，只作为界面流程证据，不能替代真实模型问答录屏或语义审核。

查询数值检查：离线合成向量中的小幅非零坐标不应被六位小数舍入抹掉；float32 转换后全零的稠密查询跳过余弦召回，有有效稀疏信号时仍能从授权语料召回。距离为 NaN / 无穷的候选不得参与该通道融合，同块其他有限通道不受牵连；这些都是故障 / 数值验证，不是模型语义质量指标。旧向量与阈值不自动修改，新评测记录 query_vector_policy 便于核对口径。

编码异常检查：用离线故障编码器返回错误维度、NaN / 无穷值或越界稀疏索引时，上传应返回 503 / `ENCODER_OUTPUT_INVALID` 且目录不变，界面保留表单并提示编码服务异常；不应把它归因于文档内容校验。检索侧异常应作为运行故障结束，无来源输出，不伪装成无依据拒答。已有向量不自动回填或修复，这些故障注入不代表真实模型效果测量。

元数据检查：上传纯空白、超过 255 字符或含 NUL 的标题、未知语言或已有文档语言不匹配时，后端应在文件复制 / 模型加载之前拒绝，目录与当前修订不变；直接调用入库服务也应在解析 / 编码前检查。合法标题保留原字形和首尾空白，不隐式合并文档身份。管理页读取服务端规则，422 时保留表单供修改，不误报为结果未知或自动重试。声明语言检查不等同于自动识别正文语言。

问题长度检查：前端显示当前上限和待发送字符数，超过上限保持原文、禁用发送，不截断文本；普通 emoji 按 Unicode 码点计数。直接调用 API 提交纯空白、含 NUL 或超限问题，应返回校验错误，不新增会话 / 消息或推进检查点。服务端拒绝后原问题回到输入框供修改，但不能覆盖正在编辑的新草稿。用 `KNV_CHAT_MAX_CHARS` 设置正整数并重启服务，该限制不限制总历史、模型 token 或费用。

会话标题搜索检查：输入关键词时不请求，点击搜索后仅筛选本人标题；刷新 / 加载更多沿用已提交关键词，未提交的编辑不改变结果范围。换词会清除旧游标，旧查询迟到不能覆盖新结果；清空后提交恢复全部会话。搜索不清空已打开的消息、不恢复检查点、不调用模型。可用 `%` / `_` 检查字面匹配，标题未包含的消息正文不会命中。

会话分页检查：侧栏首次最多显示 20 条，加载更多追加旧会话；刷新从最新一页开始，但不清空当前打开会话的消息。分页失败保留已加载内容与游标，显式重试后继续。完成问答后首页自动刷新，较慢旧分页不能覆盖新结果；列表读取不调用模型或恢复检查点。旧 `/conversations` 数组接口保持兼容，前端分页页需要同步更新后端。

长段落分块检查：上传含连续长段落、无句末标点或长英文行的资料，新草稿块正文应均不超过 700 字符，保留页码和章节路径；边界附近能放入单块的常见短型号 / 故障码保持完整。源文件和修订内容 hash 不因切分而改变，旧修订不自动重切。若要使用新切分，重新上传为草稿并按原发布流程核对；此改进不代表已测得真实检索质量提升。

上传大小检查：管理页显示服务端单文件上限；超过上限的已选文件应在提交前提示并保留表单，直接调用 API 超限时返回 413，不生成修订、不加载编码器，当前发布版本不变。恰好等于上限的有效文档可以上传为草稿，空文件返回 422。默认 20 MiB，可用 `KNV_UPLOAD_MAX_BYTES` 调整并重启后端；该限制不覆盖 multipart 进入处理函数前的临时落盘或 PDF 解压后资源开销。

登录检查：选定账号后所有账号按钮禁用，快速重复点击只发送一次登录；失败后才可显式重选。登录请求中离开页面后，迟到响应不应写入新凭据或再次跳转；登录期间其他标签页切换凭据时，旧结果不应覆盖当前账号。成功后以 hash 路由进入问答并重新核对身份，不再整页刷新。

身份加载检查：切换账号或路由后，身份确认成功前不显示旧身份或挂载目标业务页；断网导致身份读取失败时应出现重试和切换账号入口。旧请求迟到不能覆盖当前身份，旧凭据请求的 401 不能清掉新登录 token。其他标签页换账号 / 退出后当前页也应重新核对或回登录页。页面切换取消浏览器连接不代表后台业务已撤销，重新进入后仍需核对状态。

资料管理检查：上传或发布期间不能重复提交，也不能并行触发另一写操作；收到成功响应后先刷新列表再解锁。若发布成功但列表刷新失败，成功提示与读取失败分开显示，手动刷新核对后再操作。请求响应丢失时不应断言旧版本仍然有效，也不自动重发；离页取消不会撤销服务端已提交的操作，重新进入后检查修订状态再决定是否重试。

管理目录筛选检查：输入标题关键词，再组合知识库与“含草稿 / 生效 / 退役版本”；显示匹配文档数，命中文档保留全部修订，便于核对版本。标题不区分大小写，`%` / `_` 按普通字符处理，不匹配正文。无结果时清除筛选应恢复目录且不清空上传字段；刷新沿用筛选并重新计算匹配结果，列表刷新失败时即使筛选仍可操作，也不能发布。筛选只处理已加载目录，不向后台发请求、不自动上传或发布；离页后条件不保存。

已有资料新修订检查：点击目标文档行的“填入新修订”，检查上传表单的知识库、标题原文与语言准确对应；同名跨库文档不得混淆。已有表单信息会被替换，旧文件选择清空，焦点转到文件选择。此时不应有上传或发布请求，选择新文件并显式上传后仍为草稿，版本号由服务端实际提交决定；需要另外点击发布才生效。表单仍可编辑，改变知识库 / 标题可能创建另一文档。目录未核实或正在处理请求时入口禁用。

材料格式检查：使用损坏或需要密码的 PDF、非 UTF-8 Markdown 或含 NUL 的文本上传，应返回 422 / DOCUMENT_PARSE_INVALID，界面显示格式要求、保留表单且不自动重试，原目录和生效版本不变。重新选择有效文件后再主动提交。空 HTTP 文件仍走原空文件拒绝；没有可提取正文的材料仍走空正文校验。本轮不增加 OCR 或页数 / 解压内存 / 解析耗时配额。

来源预览检查：用键盘定位引用卡并打开，应立即显示加载状态；Escape / 关闭按钮 / 点击遮罩均能关闭，焦点回到引用卡。慢请求期间关闭后再打开另一来源，旧响应不得覆盖新正文；关闭并开始新会话或离开聊天页后，迟到响应不得重新弹窗。失败时不保留旧正文，重新打开才重试，每次仍由后端重新鉴权。

`backend/tests/test_chat_api.py` 覆盖确认恢复、账号归属、过期只读状态和拒答回放；前端 `web/tests/` 使用 jsdom 覆盖交互、失败重试、会话切换与 SSE reader 清理。它们不替代真实浏览器录屏或人工语义审核。

升级已有实例需在 `backend/` 执行 `uv run alembic upgrade head`。`0002` 保存消息错误码；`0003` 将消息默认时间改为实际插入时间，避免同事务消息按随机 UUID 回放。历史记录不会被改写；旧记录若缺少错误码或时间相同，无法事后恢复其拒答标签或确切先后顺序。

`0004` 补充同知识库同标题的文档唯一约束与每文档单个生效修订的部分唯一索引。已有重复数据会使升级失败，需要核对后处理，迁移不会自动删改旧资料。上传空正文、编码结果数量不足或语言与已有同名文档不一致时会返回验证错误；当前生效版本继续可用。

`0005` 添加新请求轮次标记和最终消息唯一约束，支持已完成检查点的答案补存。升级不回填旧会话，需在启动本轮代码前执行迁移。

`0006` 为转交记录添加创建时间与排序索引。已有记录保留未知时间，新记录使用数据库实际插入时间；升级后再启动带记录列表的服务。

v2-m3 检索对照和当前13份语料的三组留出消融已完成，精排保持默认关闭。2026-11-09 真实 LLM dev 20 例的快照、Codex 审核与仍存在的语义误拒见评测报告第20节；运行后字形 / 提示修改及其验证边界见第22节。脚本模型的前端流程录像已完成，未标注真人审核页见 backend/eval/REVIEW.md 第6节。待补齐的真实交付仍包括真人支持度审核、后次提示修改的真实验证、外部独立阈值校准、更多语料和真实模型问答录屏。不能以固定回答、离线重放或单元测试数字替代这些证据。
