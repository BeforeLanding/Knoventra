# Knoventra v4 演示脚本与录屏清单

本脚本按 [v4 计划](knoventra-v4-plan.md) 第 2.1 节的七个故事编排。所有账号、机台、日志和资料都是虚构的。

## 两种演示方式

| | 离线容器演示（默认） | 真实模型演示 |
|---|---|---|
| 启动 | `docker compose -f deploy/compose.demo.yaml up --build -d --wait`，打开 `http://127.0.0.1:8088` | 按 README 配置 `backend/.env` 的模型，并启动 ES、Redis、MCP |
| 回答 | 固定回答，标注“演示用固定回答”；只按关键词决定调用哪个工具 | 真实模型，规划节点开启 |
| 费用 | 无模型调用 | 每次提问都是付费调用，录制前需单独批准 |
| 能证明什么 | 权限、检索、槽位、确认、派单、记忆复核、MCP 等服务端行为 | 再加上改写、意图路由和回答质量 |

离线演示里，选择工具的是一段固定脚本（`backend/dev/mock_server.py`），之后的检索、权限、槽位合并、专家推荐、机型澄清、记忆召回与复核都是真实的服务端代码。七个故事都由 `dev/check_demo.py` 自动核对（CI 中普通模式和 `--mcp` 模式各跑一次），下面的提问用词与核对脚本一致。

离线编码器是按词面计算的哈希向量，不是语义模型，所以有两处用词要贴近资料原文（见故事 3 和 7）。换成 BGE-M3 和真实模型后没有这个限制，但那部分没有做付费验证。

## 七个故事

每次录制前用一个全新的演示栈（先 `down -v`），否则历史记忆和已发布的案例会改变结果。

### 1. 经验检索
- 账号：SG · Ops（`sg-ops`）
- 提问：`WX-38 切换 tank 时报 alarm、pump 不转怎么办`
- 看点：来源卡是去重后的现场案例（`CASE-…`），注明修订和页码；点开预览可见脱敏后的原文。

### 2. 机型澄清
- 新会话提问：`spindle 更换扭矩多少`
- 看点：系统不给答案、不出来源，先问“请问你的机台是哪个机型？”，因为《SOP-WCL-380120-002 Spindle 更换》对 WX-38 和 WX-P 写了不同扭矩。
- 回答：`WX-38`。来源只来自 WX-38 的内容，不会混入 WX-P 的分节。

### 3. 拼写错误与编号
- 提问：`mix tank trouble shotting`（故意拼错）。看点：纠错表和 ES 让它命中 “trouble shooting” 相关案例。
- 提问：`SOP-WCL-380110-001 液位报警后 interlock 怎么复位`。看点：按编号精确召回该 SOP。
- 用词说明：只报编号、不带主题词的问法（如 “SOP-WCL-380110-001 讲的是什么”），在离线演示里会因哈希向量分数低于证据闸门而拒答；编号召回本身是命中的，可在开发环境的 `/api/v1/debug/search` 里看到 `ident` 通道的结果。

### 4. 人员查询
- 提问：`谁会做 golden check`
- 看点：走技能表的结构化查询，不检索文档、不出来源卡；按掌握程度和作业次数排序。
- 对照：切换 SG · HR 问同一句，提示技能表只对 Ops 开放。

### 5. 求助单
- 新会话提问：`WX-38 机台 630101 切换 tank 时报 A-1301，pump 不转，帮我提个求助单`
- 看点：缺“已尝试的步骤”，系统追问一项，不建单。
- 回答：`已经重新插紧 LS-2，还是不行`
- 看点：确认卡标题为“求助单确认”，列出机台号、机型、告警码、现象、已尝试步骤，以及推荐专家和理由（Tan Wei Ming，技能为掌握、同区域、当前未结单数）。点“确认提交求助单”后建单并自动派单，状态为“已派单”。刷新或重复提交不会多建一张。

### 6. 跟进与沉淀
- 切换 SG · 现场工程师 Tan Wei Ming，打开“专家工作台”，选中这张单：开始处理 → 在“说明”里填 `更换 LS-2 液位传感器并重新校准后恢复，切换 tank 不再报 A-1301` → 提交解决方案。
- 看点：处理记录逐条留痕；“案例沉淀”显示草稿等待审核。
- 切回 `sg-ops`，打开刚才的会话：顶部出现“你的求助单已更新”，内容是专家的解决方案。
- 切换 IT · 管理员，在“资料管理”的 `field-cases` 里找到 `HELP-…` 草稿，先预览再发布。
- 切回 `sg-ops` 新会话问 `WX-38 机台 630101 切换 tank 时报 A-1301，pump 不转`，来源里出现刚发布的 `HELP-…` 案例。可以在发布前先问一次作对照：草稿检索不到。

### 7. 记忆
- `sg-ops` 新会话问：`上次 630101 切换 tank 时报 A-1301、pump 不转的求助单后来怎么解决的`
- 看点：回答引用以往记录里的处理结果。打开“我的记忆”可以看到这条记录，也能逐条删除。
- 用词说明：离线哈希向量按词面匹配，问法要带上机台号和现象；“上次那个 alarm 后来怎么解决的”这类简短问法在离线演示里召回不到。
- 撤权与撤回（可选）：管理员发布一份引用过的资料的新版本后，旧版本变为 RETIRED，引用旧版本的那条记忆不再被使用（`check_demo.py` 用 E17 v1 → v2 核对这一点）。
- 不演示的部分：计划故事 7 的前半句“长对话自动压缩”。历史超过 6000 个近似 token 才会压缩，演示里很难自然触发，所以这里不展示；压缩、摘要滚动和 Redis 丢失后重建由 `backend/tests/test_working_memory.py` 覆盖。不要在录屏里声称演示了压缩。

## 录屏清单

**录制前**
- [ ] `docker compose -f deploy/compose.demo.yaml down -v` 后重新 `up --build -d --wait`，六个服务都是 Healthy。
- [ ] 浏览器窗口固定为 1280×800 或更大，关闭书签栏和扩展图标；缩放 100%。
- [ ] 准备好七个故事的提问文本，复制粘贴，避免现场打错字（故事 3 的拼写错误是故意的）。
- [ ] 确认画面里只有虚构数据：账号都是 `@example.test`，机台和公司来自生成脚本。
- [ ] 不录终端里的 `.env`、密钥和 token；演示用的工具 token 密钥只写在 `compose.demo.yaml` 里，也不要放大展示。

**录制中**
- [ ] 每个故事开头说明当前账号（右上角显示区域和部门）。
- [ ] 故事 1、3：点开一张来源卡，展示修订号和原文预览。
- [ ] 故事 2：停在追问上，说明为什么不直接回答。
- [ ] 故事 5：在确认卡上停留，逐项指出槽位和推荐理由；点提交后刷新一次，说明不会重复建单。
- [ ] 故事 6：工作台的处理记录、需求方的更新提示、管理员发布前后的检索对比。
- [ ] 故事 7：回答之后打开“我的记忆”。
- [ ] 画面上出现“演示用固定回答”时，口头说明这是离线演示，回答文字是固定的。

**录制后**
- [ ] 核对视频里没有真实姓名、客户名、口令或本机路径。
- [ ] `docker compose -f deploy/compose.demo.yaml down -v` 清理演示数据。
- [ ] 如果要改用真实模型录制，先确认费用并单独批准，再录。

## 不在演示范围内

- 模型指标：Agent 层留出集已用真实模型测过（路由、澄清、槽位、建单等，结果见[评测报告](evaluation-report.md)第 26 节），但演示栈使用离线脚本模型和固定回答，因此演示中不展示任何模型指标。
- 仍未测量的项目：查询改写开/关对检索层的对比、滚动摘要质量与压缩后槽位保留率、情景记忆召回质量（0.5 阈值未标定），演示中同样不报告数字。
- 生产部署、SSO、IM 通知：v4 明确不做（计划第 6 节）。
