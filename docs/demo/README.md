## 2026-11-09 当前多轮确认流程截图

以下是当前明确转交监督路径的浏览器验证，属于静态截图，未替换上述旧录像。使用新建隔离库 `knoventra_ui_guard_20261109`、13 份虚构资料 / 23 个生效块、Hash 编码器和脚本模型；演示进程清空模型密钥、地址及型号，没有调用外部 LLM。

1. SG / Ops 提问“E17 设备报代码 42 先查什么”，来源预览显示修订 1、第 2 页及四条原文步骤：[来源预览](current-ui-20261109/01-source-preview.jpg)。该图在布局修复前截取，顶部导航存在窄窗口逐字换行。
2. 同会话发送“这个问题我想转人工”，确认卡同时保留先前故障问题和当前请求。此时直接查询业务库为 1 条 PENDING 确认、0 条转交；刷新浏览器后重新打开会话，确认卡仍在：[刷新恢复](current-ui-20261109/02-confirmation-restored.jpg)。同时修复顶部布局，使 615 像素窗口内导航可读、身份区域另行换行。
3. 点击“确认转交”后收到 OPEN 回执；打开本人记录并刷新，仍只有一条完整摘要。直接查询业务库为 0 条 PENDING 确认、1 条转交：[本人记录](current-ui-20261109/03-single-escalation.jpg)。

本次只验证来源预览、多轮确认恢复与记录显示，不重新声称覆盖所有账号 / 发布场景，也不将脚本回答视为真实模型质量或真人支持度审核。前端 145 项测试、生产构建和零警告 lint 通过；后台规则沿用此前通过的 697 项 CI，本次未修改后端。演示服务验证完毕后停止，隔离数据库保留。
